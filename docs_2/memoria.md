name: proyecto-chapala description: Proyecto CHAPALA — sistema Django para All Oil Services (AOS): inventario químico (mychapala) + reportes de fluidos de perforación estilo ONE-TRAX (reportes) sources: [chat] aliases: [chapala, proyecto chapala, all oil services, aos, one-trax]
Proyecto CHAPALA: sistema modular en carpeta "Proyecto CHAPALA" en su máquina (Windows), Django + PostgreSQL/SQLite, para All Oil Services, C.A. (AOS)
dos apps Django conviven en el mismo proyecto: mychapala (inventario químico, en producción real) y reportes (esquema estilo ONE-TRAX de M-I SWACO: Pozo → Intervalo → ReporteDiario, con UUIDs)
tiene documentación extensa del proyecto en documentation/Contexto/ (diccionario de datos, estructura de tablas, fórmulas, próximos pasos, etc.) más un "manual resumido, esquema.pdf" que aterriza en detalle los pasos 1-7 del manual ONE-TRAX (configuración de pozo, intervalos, catálogos de fosas/pérdidas, geometría, contabilidad volumétrica, cierre de intervalo)
usa control de versiones con git; tiene ramas "main" y "Archivos-de-contexto" en GitHub — la rama "Archivos-de-contexto" se usó para subir documentación vía GitHub web y quedó divergente de "main" (donde vive el código de la app reportes), lo que causó que al hacer pull los archivos fuente de reportes/ (models.py, views.py, migraciones, templates, static) desaparecieran del working directory local aunque seguían intactos en el historial de "main"
